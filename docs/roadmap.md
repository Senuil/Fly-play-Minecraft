# 下一階段與驗收條件

v0.2 已加入漫遊、跟隨、台階跳躍、地形停止與卡住恢復。這些玩家輔助由工程層提供，
神經模型仍為六神經元 probe；還不是完整玩家。

**下一個功能里程碑：採集木頭。** 加入目標狀態、方塊辨識、接近、挖掘、拾取與背包檢查，
先驗收「找到一棵可接近的樹 → 取得一個原木 → 停止並回報」。
接著才擴充工作台／工具合成、食物與生命管理、庇護所、路徑與短期記憶。
每項技能標明是神經控制、工程規則或規劃器，並在固定測試世界驗收。

1. **在新筆電與目標伺服器驗收。**
   取得 CPU、VRAM、driver 與實際 Java Edition 版本，執行 hardware_info、probe benchmark、
   本地網路整合測試。再加入私人 Paper 1.21.9 平地世界，記錄至少 5 分鐘的位移、角度、
   p95 延遲、失敗率；確認停止神經服務、死亡、重生、斷線時 bot 都能停止或重新建 session。

2. **從工程 probe 換成生物可解釋子迴路。**
   查 FlyWire 相同版本的 cell type、hemisphere、descending neurons 註解；
   選左右對應的輸入／中間／輸出路徑，附每個 root ID 的來源與映射理由。
   不把沒有確認的 ID 稱為 DNa01 / DNa02 等已知細胞類型。
   保留誘導子圖與被切除邊的統計；增加對稱刺激、靜默、輸出群消融、連線打亂等對照。
   驗收：刺激不同感覺通道，經可追蹤的神經路徑改變轉向；不靠直接刺激輸出細胞。

3. **建立 Brian2 參考與加速後端。**
   先鎖定同一套方程、積分步長、不應期、延遲和輸入事件序列，
   對照 firing rate、spike timing、靜默狀態和穩定性。
   評估稀疏事件驅動 CPU、PyTorch CUDA 或 GeNN，保留 `advance` 與持久狀態介面。
   驗收：相同模型與刺激下結果差異在預先訂定容差內；報告 setup、VRAM、p50/p95 分別耗時。
   20 Hz 控制目標要求每 50 ms 神經窗的 p95 運算加 IPC 低於 50 ms，不能只看平均值。

4. **逐級放大網路與感測。**
   由有意義的數百／數千神經元子迴路擴至全腦；各級都量測效能及消融對照。
   把三個幾何訊號擴成方位感覺通道、optic flow 或玩家畫面編碼，明確記錄遊戲尺度映射。
   真實複眼編碼與學習需額外模型，並非 connectome 自動提供。

5. **行為實驗與更複雜動作。**
   在 v0.2 的目標接近、障礙避讓與跳躍基礎上，驗證連續地形、移動目標，再接入採礦。
   每關有成功率、碰撞率、時間及與簡單規則 bot 的比較；固定 seeds 與世界供重播。
   PvP 或 600 模組伺服器不適合作為這個 prototype 的第一個驗收環境。
